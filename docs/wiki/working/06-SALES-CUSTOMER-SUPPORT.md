## 1. Overall vision (GTM + support lens)

Jay is sold to **partners** (agents, landlords, insurers) as the move operator that starts before the mover opens an app, and sold to **movers** as calm ownership: Jay handles, you confirm, a customer support human agent is there when it matters.

CS success is not ticket volume. It is: stuck notifications chased, false confirms never happen, cascade never loses work, distress reaches a human.

---

## 2. Who we sell / support

| Audience | Job to be done | What Jay promises |
|---|---|---|
| **Referring partner** | Hand off a mover cleanly; look competent | Named referral, watching until consent, conversion visibility (Later: weekly report) |
| **Mover** | Survive the move without drowning | One profile, honest receipts, clear You vs Jay, human escape |
| **Customer support human agent / ops** | Handle exceptions without becoming a chatbot | Named escalate path, ops console (MVP discuss), distress routing |
| **Panel / suppliers** | Fair placement + clear commerce | Ranking rules, confirm fees explicit, no fake bookings |

---

## 3. Partner narrative (sales talking points)

1. **Starts at referral**, not after the mover downloads something random  
2. **Watching gate**, no outbound spam while the mover is still deciding  
3. **Collect once**, discovery feeds ranking; less re-asking  
4. **Confirm = commerce**, transparent, receipt-backed  
5. **Date change survives**, cascade; work is not silently lost  
6. **Day 0 capture**, meters / access evidence for deposit and disputes  
7. **Stickiness after move-in**, Market + Tasks, not a dead login  

What we do **not** claim: we replace every utility portal; we bundle bills by default; we are a chatbot; voice is the only Day 0 path.

## 4. Support playbook (customer support human agent)

| Situation | Expected product behaviour | CS action |
|---|---|---|
| Mover stuck / confused | Ask Jay FAQ → escalate to a customer support human agent | Named human; no scripted bot loop |
| Distress language | Human path preferred | Priority queue; stop automation pressure |
| “Confirmed” but no receipt | Should not happen; if UI lies, incident | Ops: fix truth; never coach around false green |
| Supplier no-ACK (e.g. council) | `sent · no receipt` honest | Explain; chase job; set expectations |
| Date change mid-move | Cascade worker | Confirm nothing dropped; lost = 0 |
| Pause / opt-out | Settings kill switch | Honour immediately across jobs |
